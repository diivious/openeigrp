## Scope and contracts

`linux/code/eigrp_linux_packet.c` provides the public host-side socket,
multicast and IPv4 packet functions declared by `eigrp_sys.h`. It uses a
nonblocking, close-on-exec raw IPv4 socket per EIGRP runtime with IP protocol
88. The Linux kernel constructs transmit IP headers because `IP_HDRINCL` is
not enabled; only the EIGRP payload generated by the portable core is sent.
Receive returns the *complete* IPv4 datagram, with the network header length,
EIGRP payload length, ingress interface, source/destination IPv4 addresses and
multicast destination flag supplied independently to the portable core.

The wire profile is protocol 88, 224.0.0.10, hop limit 1, Internet-control
TOS 0xc0. `IP_PKTINFO` binds every outgoing datagram to the EIGRP interface
index and local IPv4 source, independently of the socket's most recent default
multicast interface setting. `IP_ADD_MEMBERSHIP` and `IP_DROP_MEMBERSHIP`
operate on the explicit interface index; Linux automatically releases remaining
memberships when the socket is closed. `IP_MULTICAST_ALL=0` restricts group
delivery to joins on this socket.

Inbound validation rejects short or truncated datagrams, bad IPv4 version,
invalid header sizes and total lengths, unexpected protocol, fragmentation,
invalid IPv4 header checksums, missing or truncated ancillary metadata,
interface-index mismatch with the published inventory, and inconsistent packet
destinations. The provider does **not** examine EIGRP opcodes, checksums,
authentication, TLVs, RTP or DUAL state. IPv4 options are accepted when
well framed and checksummed. `recvmsg` is nonblocking; a malformed packet is
dropped without closing the socket and the next datagram can be received.

Netlink interface inventory currently publishes only default-VRF
interfaces. This provider therefore rejects nondefault VRF runtimes and uses
`eigrp_sys_interface_walk()` to confirm ingress ownership before emitting
`EIGRP_VRF_DEFAULT` in the receive metadata. This is **not** nondefault Linux
VRF support. Future VRF support must bind receive sockets to the appropriate
Linux VRF and resolve ingress VRF identity from host interface state.

`eigrp_linux_packet_fd()` returns a borrowed fd for the future daemon event
loop. The event loop must register for readability after successful
`eigrp_sys_socket_open()`, unregister before `eigrp_sys_socket_close()`, and
call portable `eigrp_packet_read()` on readiness. No daemon event loop is
supplied. Native daemon startup, CLI, config, netlink RIB and Cisco
adjacency verification remain dependent on later integration tasks.

The daemon needs `CAP_NET_RAW` to open the socket. No arbitrary privilege
escalation or retained privileged helper is provided. Privileges should be
reduced by the process supervisor after socket creation. A failed open or
partial configuration closes the fd. The complete instance cleanup path
closes the fd and relinquishes kernel multicast membership state.

## Verification

`python3 linux/test/test_packet.py` compiles the production module into a
crafted-packet harness and checks real-kernel privilege gating. The tests
exercise source/destination/index/VRF metadata, multicast/unicast sends,
raw socket options, send errors, packet loss, bad frames, receive recovery,
repeated opens, and teardown. The existing `eigrp/test/uut/` virtual-wire
transport stays unchanged; `eigrp/test/uut/rtp-recovery/` scenarios exercise
portable RTP and convergence on loss/recovery, **not Linux raw sockets**.

`linux/test/netlab/` contains a manual Cisco interop topology and a required
packet-capture/adjacency checklist. It is blocked until an actual native
daemon with configuration, scheduling and RIB is built. Without a Cisco or
Cisco-compatible peer and `CAP_NET_RAW`, native adjacency is unverified.
